## A.2 Sentence Generation Template (Jinja2)

Each dataset has an LLM-generated Jinja2 template that converts GeoJSON properties into natural language text. The template was generated by feeding the dataset's schema to the LLM and asking it to produce a readable sentence template.

**Template for Excavation Permits:**

```jinja2
{% if location and location != "-" %}An excavation permit at {{ location }}, Københavns Kommune
{% else %}An excavation permit in Københavns Kommune{% endif %}
{% if category %} for {{ category | lower }}{% endif %}
{% if excavation_surface_type %} affecting {{ excavation_surface_type | lower }}{% endif %}.
{% if project_start %} The project runs from {{ project_start }}
  {% if project_end %} to {{ project_end }}{% endif %}
  {% if time_from and time_to %}, with daily work hours {{ time_from }}–{{ time_to }}{% endif %}.
{% endif %}
{% if client %} Client: {{ client }}
  {% if contractor and contractor != client %}; contractor: {{ contractor }}{% endif %}.
{% elif contractor %} Contractor: {{ contractor }}.{% endif %}
{% if case_number %} Case number {{ case_number }}.{% endif %}
```

**Resulting sentence (from the feature above):**

> "An excavation permit at Godthåbsvej 177 - 185, Københavns Kommune for sheet pile affecting road lane, parking area, cycle path, pavement, closer than 4 m to trees. The project runs from 06-05-24 to 01-06-26, with daily work hours 06:30–18:00. Client: CG JENSEN A/S - Fabriksparken v. Glostrup. Case number 605326."

## A.5 Query Executor — Core Function

The deterministic execution engine that all structured systems share (PageIndex and Graph-Indexed use this directly; PostGIS replaces it with SQL):

```python
def execute_plan(plan: dict, collections_dir: Path) -> dict:
    operation = plan.get("operation", "list")
    dataset = plan.get("dataset", "")
    filters = plan.get("filters", [])
    spatial = plan.get("spatial", {})

    # Load GeoJSON features
    dataset_path = collections_dir / f"{dataset}.json"
    features = _load_geojson(str(dataset_path))

    # Apply property filters (AND logic)
    filtered = []
    for feature in features:
        if _apply_filters(feature, filters):
            filtered.append(feature)

    # Apply spatial filter (haversine distance)
    center_lat = spatial.get("center_lat")
    center_lon = spatial.get("center_lon")
    radius_m = spatial.get("radius_m")

    if center_lat and center_lon and radius_m:
        spatially_filtered = []
        for feature in filtered:
            feat_lat, feat_lon = _get_feature_centroid(feature)
            dist = haversine_m(center_lat, center_lon, feat_lat, feat_lon)
            if dist <= radius_m:
                spatially_filtered.append((feature, dist))
        spatially_filtered.sort(key=lambda x: x[1])
        filtered_with_dist = spatially_filtered
    else:
        filtered_with_dist = [(f, None) for f in filtered]

    # Execute operation
    if operation == "count":
        return {"count": len(filtered_with_dist), "features": [...]}
    elif operation == "nearest":
        return {"feature": filtered_with_dist[0], "distance_m": ...}
    elif operation == "list":
        return {"count": len(filtered_with_dist), "features": [...]}
```

Source: `shared_rag/query_executor.py`

## A.6 Agent Tool-Use Loop

The core agentic loop — the LLM decides which tools to call, observes results, and iterates:

```python
def run_agent(question: str, client) -> AgentTrace:
    messages = [{"role": "user", "content": question}]
    tool_call_count = 0

    while tool_call_count < MAX_TOOL_CALLS:  # max 8
        response = client.messages.create(
            model=LLM_MODEL,
            system=AGENT_SYSTEM_PROMPT,
            tools=TOOL_DEFINITIONS,
            messages=messages,
        )

        # If no tool use → agent is done, extract final answer
        if not any(block.type == "tool_use" for block in response.content):
            trace.final_answer = extract_text(response.content)
            break

        # Execute each tool call
        messages.append({"role": "assistant", "content": response.content})
        tool_results = []
        for block in response.content:
            if block.type == "tool_use":
                tool_call_count += 1
                output = execute_tool(block.name, block.input)
                tool_results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": json.dumps(output),
                })

        # Feed results back → LLM decides next action
        messages.append({"role": "user", "content": tool_results})

    return trace
```

## A.7 Cypher Generation Prompt (Graph-Indexed)

The system prompt that teaches the LLM to generate Neo4j Cypher queries for dataset selection:

```
You generate Cypher queries for a Neo4j graph of Danish geospatial datasets.

RULES:
1. Return ONLY the Cypher query. No explanation, no code fences.
2. Always RETURN d.key.
3. Use Topic nodes, Property nodes, and text matching to find relevant datasets.
4. Consider synonyms: "play area" = playground, "bike rack" = bicycle parking,
   "water bottle" = drinking water, "loo" = toilet, "camping" = campsites.
5. For location-specific questions, filter by Municipality relationships.
6. Prefer traversing Topic/Property edges over text matching when possible.

## Graph Schema
- (Dataset)-[:LOCATED_IN]->(Municipality)-[:PART_OF]->(Region)
- (Dataset)-[:HAS_TOPIC]->(Topic)
- (Dataset)-[:HAS_PROPERTY]->(Property)
- (Dataset)-[:SHARES_TOPIC]->(Dataset)

## Example:
MATCH (d:Dataset)-[:HAS_TOPIC]->(t:Topic {name: 'construction'})
RETURN d.key, d.title
```

## A.8 LLM Judge — Structured Tool-Use Scoring

The judge uses Claude's tool_use API with forced tool choice to guarantee a valid 0-3 score:

```python
JUDGE_TOOL = {
    "name": "submit_score",
    "description": "Submit evaluation score",
    "input_schema": {
        "type": "object",
        "properties": {
            "score": {"type": "integer", "enum": [0, 1, 2, 3]},
            "reason": {"type": "string"}
        },
        "required": ["score", "reason"]
    }
}

response = client.messages.create(
    model=LLM_MODEL,
    system="Score: 3=correct, 2=close, 1=partial, 0=wrong.",
    tools=[JUDGE_TOOL],
    tool_choice={"type": "tool", "name": "submit_score"},  # FORCES structured output
    messages=[{"role": "user", "content": f"Question: {q}\nExpected: {expected}\nGenerated: {generated}\n\nEvaluate."}],
)

# Guaranteed to return {"score": N, "reason": "..."} — no parsing needed
score = response.content[0].input["score"]
```

## A.9 PostGIS Spatial Query (replacing Python haversine)

For the PostGIS system, the Python query executor is replaced with spatial SQL:

```sql
-- Count excavation permits within 300m of Tivoli
SELECT count(*) as cnt
FROM excavation_permits_koebenhavn_kommune
WHERE ST_DWithin(
    geom::geography,
    ST_SetSRID(ST_MakePoint(12.5681, 55.6737), 4326)::geography,
    300
);

-- Find nearest excavation to a point
SELECT *, ST_Distance(
    geom::geography,
    ST_SetSRID(ST_MakePoint(12.5681, 55.6737), 4326)::geography
)::int as distance_m
FROM excavation_permits_koebenhavn_kommune
ORDER BY geom <-> ST_SetSRID(ST_MakePoint(12.5681, 55.6737), 4326)::geometry
LIMIT 1;
```
